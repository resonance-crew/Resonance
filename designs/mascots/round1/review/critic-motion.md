## 看提案之前先寫下的看法

（看提案之前寫下）共振的角色要做對四件事。第一，它必須是首頁那個世界裡的居民，不是貼上去的貼圖：要和三團會長頸、會融合的漂移色塊共存，和「一支筆」線條同一種手感，並且同時在奶油紙和深色夜紙上成立。第二，情緒要靠眼睛和一個招牌部位讀得出來，縮到手機上 80–100px 也不能糊成一顆豆子。第三，結構上最好是「大部分剛體、只有一個會形變的招牌器官」：剛體部件拆成獨立圖層，烘焙後只動 transform 和 opacity，GPU 合成就能跑，招牌器官再用骨骼或少數狀態處理。紙紋、蠟筆顆粒這類即時濾鏡只能當烘焙工具，不能在首頁即時跑，否則會和現有 30fps 的 metaball canvas 搶主執行緒。第四，它要安靜：不進入主標與下載區所在的內容欄，`prefers-reduced-motion` 時要能完全靜止仍然好看。品牌的「共振」最好透過兩個角色之間的行為（靠近、同步、碰觸後漾開的波線）自然發生，而不是畫在身上的符號。

## A｜聽芽 Tingya（色鉛筆小生物）

### 優點

- 拆件結構三案最健康：a-torso 底下依序是 tail、body、antenna、arm-l/r、face，face 內再分眼、眉、嘴、頰，每個群組都在註解標了 pivot。我實際套了：臉平移 14px、芽旋轉 +14°／−18°、身體擠壓 scale(1.06, 0.9)、眨眼 scaleY 0.12。接縫和芽根都沒有破（review/motion-poses.png、motion-zoom.png）
- 除了芽以外全部是剛體，探頭、走入（雙腳小跳加擠壓）、停留（呼吸、眨眼、臉朝游標滑動）、離場，用 CSS／WAAPI 就能做完。芽的「捲緊 ↔ 舒展」是一條連續的情緒刻度，最適合做「看向訪客、在聽」這種 idle
- 濾鏡成本三案最低：整隻完整點陣化一次 8.9ms，拿掉濾鏡 2.4ms（headless Chrome、軟體點陣、440px）。B、C 約 28–30ms
- 顏色全寫成 CSS 自訂屬性（18 處 var(--a-…)），換紙只要覆寫變數。另外有用同一支筆重畫的小尺寸版本，48px 剪影仍認得出芽
- 情感感染力最直接：眼睛低位、間距寬，加上眉的斜度與上眼瞼的高低，靜態也讀得出好奇或感動

### 缺點

- character.svg 不是合法 XML：第 3 行註解裡的 `--a-ink, --a-fur` 含雙連字號，xmllint 會報錯。我實測以 <img src> 載入時直接顯示破圖。獨立開檔、當 CSS 背景、匯入 Figma／Rive／Illustrator 都會失敗，只有內嵌在 HTML 才看得到（concept.png 能渲染是因為 render.sh 用 HTML 解析器）
- 招牌的「舒展／捲緊」不能只靠旋轉。要嘛 3–4 張狀態交叉淡入：兩張鉛筆線圖交疊淡入淡出時會出現雙影，時長要壓在 150ms 內。要嘛用 Rive 骨骼鏈加網格。這是 A 唯一、但也是最核心的動畫成本點
- 白天主毛色 L86% 與奶油紙、桃色色塊太接近，站在桃色色塊前幾乎只剩輪廓線撐住。夜紙版的奶油輪廓 L88% 疊在毛色 L80% 上幾乎看不見，整隻變成一團平的奶茶色（motion-poses 的 A night）
- 烘焙成點陣後 CSS 變數就失效，日、夜要兩組圖，或把輪廓層獨立出來用 mask 染色
- 除了芽，身體與臉都在「豆形、點眼、腮紅」的類型慣例裡，辨識度幾乎全押在芽上

### 必修

- 修正 character.svg 的 XML 合法性：把第 2–3 行註解裡的 `--a-ink, --a-fur…` 改成不含雙連字號的寫法（例如「a-ink／a-fur 等 CSS 變數」），用 `xmllint --noout character.svg` 驗證通過，並確認以 <img src> 單獨載入能正常顯示
- 把 a-antenna 拆成兩段：a-antenna-stem（pivot 407,316，莖離開頭頂處），底下再包子群組 a-antenna-curl（pivot 設在莖與捲的交界，座標寫進註解）。這樣「點頭、伸向另一隻、捲緊一點」可以只靠兩段旋轉加縮放做出，不必每個狀態都重畫
- 調夜紙變數，把輪廓和毛色的明度拉開：例如 --a-ink 提到約 L93%、--a-fur／--a-under 降到約 L70%／L58%，讓排線和輪廓在深色紙上重新看得見。用 render 在 oklch(21% 0.012 60) 夜紙上確認，不是一團平的奶茶色

### 相似 IP 風險

中低。頭上長植物最接近皮克敏，但聽芽的芽是粗捲細莖、沒有葉也沒有花、和身體同色，夠區隔。真正的風險在身體與臉：「直立豆形加深色點眼加腮紅」是 LINE 貼圖小生物的通用臉（角落生物、卡娜赫拉系），縮圖時會被讀成同類。提案自己做的史萊姆、小豬尾、垂耳兔排除都合理。

### 備註

實作路線：沿用 _build 產生器，每個部件直接輸出 2× WebP，日、夜各一組，估每組約 80–150KB。HTML 絕對定位排出部件，用 WAAPI 只動 transform 和 opacity。第一期芽用 3 張狀態交叉淡入，第二期再改成 Rive 骨骼鏈；兩角色互動多了再整體搬進 Rive 的 state machine。位置：桌機放在內容欄（約 560px）外側，主標右邊鼠尾草色塊旁或下載區左下，高 160–200px。手機只做「芽先從右緣探出、身體只露半個」的 70–90px 版。reduced-motion 時顯示靜態主姿勢，眨眼可留。和 DriftingBlobs 共用同一個 requestAnimationFrame（rAF），離開視窗暫停。人日粗估同意提案的 9–12，芽若第一期就上 Rive 再加 1 天。檢查圖都在 /private/tmp/claude-501/-Users-ncchen-Documents-Resonance/3169a3a1-407a-43b9-a40d-6b2f52c2622f/scratchpad/mascots/review/motion-poses.png、motion-zoom.png、motion-sizes.png。

## B｜漾漾 Plip（蠟筆流體生命）

### 優點

- 唯一「本來就住在首頁色塊裡」的設計：頭和池子之間的收腰，就是 metaball 兩團快融合時的頸。DriftingBlobs 的 World 已公開 lobeAt()，頭要跟著色塊漂是做得到的。兩池相融、漣漪交疊，是三案中最直接的「共振」畫面
- 頭用漸層 mask 淡進脖子，我把頭再轉 −15°，接縫仍然自然（motion-zoom 的 B1）
- 出場不需要走路：升起、伸長脖子探頭、沉回池子都很省版面。手機上只把脖子從邊緣伸進來，正好適合窄螢幕
- 蠟筆厚塗、無外框、兩色在頸部交疊，質感三案最柔、最療癒，色相都取自卡片色系（55／290／18）
- 動態表現的天花板最高：伸長是好奇、沉下是害羞、顏色暈開是感動，形變本身就是表情

### 缺點

- 核心動作全是非剛體（脖子伸縮與彎曲、池子壓扁、頭沉入）。紙紋烘在各部位裡，形變時顆粒會被一起拉伸：我把 b-neck 做 scaleY 1.35，顆粒明顯拉成直條（motion-zoom 的 B2）。用 Rive 網格變形也一樣會拉伸貼圖
- 濾鏡成本最高：整隻完整點陣化 29.5ms，無濾鏡 4.8ms。全檔用 5 個濾鏡、26 處引用、3 個大範圍 mask，401 個 path，檔案 153KB
- 夜紙：打底層 --b-under-* 是沒有毛邊的實心形，把蠟筆邊緣的紙紋縫全部填平，頭在夜紙上變成硬邊圓盤；頭左下與頸交界還有一塊灰濁的過渡（motion-zoom 的 B night）
- 首頁夜色塊是 L 約 25–30% 的深色，而 b-pool 夜間是 L68% 的亮薰衣草。「池子就是那團色塊」在深色模式下對不上
- 要跟 canvas 裡 30fps 的色塊位置同步，必須在 DriftingBlobs 開對外介面、處理兩套迴圈的節奏。前端成本最高，也最難事先估準
- 靜態剪影容易讀成燈泡、蘑菇或神燈精靈。水滴眼尖端朝內讓表情偏擔心；縮到 48–64px 時臉幾乎看不見，從池面長出的手也常被讀成尾巴或觸手

### 必修

- 夜紙打底層要內縮：對 b-pool、b-neck、b-head-fill 的 --b-under-* 打底，用 feMorphology erode 內縮約 6–8px，或讓它跟著 b-f-tooth1 的邊緣衰減一起過濾。這樣夜紙上邊緣仍是蠟筆的斷口毛邊，不是硬邊圓盤，也要消掉頭左下的灰斑
- 紙紋從各部位抽出：把 b-f-tooth1／b-f-tooth2 的紙紋從各部位的群組裡拿出來，改成整隻角色最上層一個共用的紙紋遮罩（螢幕空間，不跟部位一起縮放）。各部位只保留色面和 warp 邊緣。在 gen.py 加一張 b-neck scaleY 1.35 的檢查渲染，確認顆粒不再被拉長
- 在 character.svg 裡定案池子和首頁色塊的關係：讓 b-pool 和 b-ripples 可以獨立隱藏，頸根下緣改成能接到任意底色的淡出；夜紙檢查圖改用首頁夜色塊的實際色值（約 L28% 薰衣草）當池子，確認頭和頸仍然讀得出來

### 相似 IP 風險

中。最接近寶可夢的臭泥（從自己的一灘裡升起、伸出一隻手），提案已主動排除下垂手臂和大嘴。頭頂的旋和蚊香蝌蚪有點聯想，但位置和尺寸不同。靜態剪影另有「神燈精靈」的通俗聯想；整體還不到抄襲，但辨識度要靠動態撐起來。

### 備註

實作路線：我不建議走提案首選的 Rive 網格，因為會連紙紋一起拉伸。建議頭、眼、手、旋做成烘焙圖層，只動 transform；頸和池直接交給現有 metaball 引擎畫：頭底一個 lobe、池一個 lobe，頸就是自然長出來的 neck。顆粒用和 hero 相同的螢幕空間 ShapeGrain 疊上。這是唯一能讓「伸縮不拉紋、又和首頁同一套語言」的做法，但要改 DriftingBlobs。人日我估 12–16，高於提案自估的 11–13，風險集中在色塊耦合和夜色。位置：只能放在色塊裡，桌機右下的薰衣草團或主標右側；手機只做從右緣伸頸。reduced-motion 時頭靜止坐在池裡。

## C｜摺摺 Tuck（撕紙拼貼紙偶）

### 優點

- 最天生的紙偶：全部是剛體紙片加縫線關節，四段動態純 transform 就能做完，第一期完全不需要 Rive。風琴腿 scaleY 就是走路、蹲、起跳；折角翻面就是脫帽式的招呼；左上小紙片是免費的延遲次要動態
- 夜紙三案最強：撕邊的白纖維本身就是外輪廓，深淺色可以共用同一組顏色、同一組烘焙圖（motion-poses 的 C night、motion-sizes）。64px 仍清楚，折角三角形一眼可辨
- 原始檔最小：32KB、32 個 path，A、B 約 150KB。濾鏡雖重（整隻 27.8ms，無濾鏡 0.6ms），但成本全在材質上、與形狀無關，烘焙後幾乎歸零
- 眼白紙片有 clipPath，瞳孔平移 ±5px 不會跑出眼白（實測）
- 折角的數學就是沿折線鏡射，提案已寫好 rotate(θ) scaleY(−1) rotate(−θ) 的翻面公式
- 材質語言離通用 AI 吉祥物最遠。系列化軸（紙材、撕法、保存方式）能同時改變剪影、質感與動態節奏，差異化潛力三案最高

### 缺點

- 拆件有結構錯誤：c-arm-l／c-arm-r 是 c-tuck 的直接子層，不在 c-body 裡，身體搖擺、呼吸、落地壓扁時手會留在原地脫節
- 折角只有背面（米白寫字面）：照註解公式掀開後，看到的仍是寫字面（motion-poses 的 C flap open）。敘事和機構也相反：折著時字已經露出，「掀開給你看」反而會把字藏起來
- 腳包在 c-leg-* 裡，風琴腿 scaleY 0.6 時腳被壓成一條線（motion-poses 的 C legs 0.6）
- 顏色全部寫死在屬性和濾鏡 flood-color 裡（0 個 CSS 變數）。夜紙剛好不用換色，但日後要配 sage／lavender／yellow 主題色時，得回產生器重出
- 臉偏通用而且有點僵（大白眼紙片、鉛筆瞳、微笑弧），整體易讀成棕色餅乾或馬鈴薯；描圖紙手像繃帶或襪子。牛皮紙色比 A、B 灰暗，「溫暖療癒」較弱，也離業主優先的色鉛筆／蠟筆媒材最遠

### 必修

- 把 c-arm-l、c-arm-r 連同縫線移進 c-body，或新增一個 c-torso 包住 body 和雙手、腿留在外面，pivot 不變。再套一次 c-body rotate(6°) 加呼吸 scaleY 0.985，確認手跟著身體走
- 補上折角正面並重放字跡：在 c-flap 補一個牛皮紙正面 path，翻面時 scaleY 過 0 就切換正反面。字跡移到折角底下的身體區域（折著時被蓋住、掀開才看得到），讓「掀開給你看」在機構和敘事上都成立
- 把腳拆成獨立的 c-foot-l／c-foot-r（pivot 在腳底中心），不包在 c-leg-* 裡：腿縮放時腳只跟著腿底端位移、本身不縮放，並在註解寫明跟隨規則

### 相似 IP 風險

低。紙偶世界最近的是 Tearaway 的 Iota 與 Paper Mario，但摺摺沒有信封矩形、郵票或黑色粗外框，材質語言原創。縮圖時「棕色圓身加白眼加腮紅」會往 LINE FRIENDS 的 Brown、餅乾或馬鈴薯那邊靠，要靠折角和風琴腿拉回來。

### 備註

實作路線：每片紙烘一張 2× WebP，含白纖維邊與膠影，日夜共用一組，估全隻約 60–120KB。用 DOM 或 SVG 紙偶加 WAAPI；折角兩面用 scaleY 過 0 切換。第一期不需要任何函式庫，互動狀態變多時再上 Rive 骨架。人日估 7–10，三案最低；第二隻角色因為拆件、互動邏輯共用，約再 5–6 天。位置：桌機站在內容欄外的「地面」，下載區左下或桃色色塊前，120–160px。手機一隻，放在「成為一群最早說故事的人」那一列下方，80px 左右，或從右緣斜身探頭。reduced-motion 時顯示靜態站姿。最獨特的出場「平躺的紙掀角、腿展開站起來」做起來也只是三段 transform。

## 比較

以下從前端與動畫實作的角度比較，同時兼顧業主列的六個面向。

**所有方向的共同前提**
- 三案的 feTurbulence、feDisplacementMap、feMorphology 都只能當「烘焙工具」，不能在首頁即時跑。
  - 實測整隻完整點陣化一次：A 8.9ms、B 29.5ms、C 27.8ms；拿掉濾鏡分別是 2.4、4.8、0.6ms（M 系列 Mac、headless Chrome 軟體點陣、440px）。
  - SVG 裡任何一個部位動一下，Chrome 都會重新點陣整個 SVG 圖層。換到中階手機約慢 3–5 倍，B、C 若保留即時濾鏡會掉到 10fps 以下。
  - 我也把 C 的 userSpaceOnUse 2200×1600 濾鏡區改成 bbox，只省約 7%，所以成本來自濾鏡本身，不是濾鏡區太大。
- 統一管線：產生器 → 每部件 2× WebP 或 AVIF → 絕對定位，只動 transform 和 opacity，交給 GPU 合成 → 和 DriftingBlobs 共用一個 rAF、離開視窗暫停、`prefers-reduced-motion` 時只留靜態。
- 版面：三者都不進內容欄（約 560px）。桌機放兩側，高 120–200px；手機一次一隻，以「從邊緣探頭」為主。

**品牌契合度**
- B 最直接：角色就住在現有色塊裡，兩池相融就是「共振」。
- A 次之：傾聽、被故事養大，很安靜地呼應。
- C 以「有人寫過字、折了角想再回來看的紙」貼近故事卡片，但也最接近「一張卡片長了臉」的符號化風險。

**情感感染力**
- A 最強：眼睛加上芽的捲緊／舒展，靜態就能讀出情緒。
- B 要靠動態；靜態時水滴眼偏擔心。
- C 的臉最僵，情緒主要靠紙的物理（折角、腿）。

**視覺辨識度**
- C 縮到 32–64px 最穩，夜紙也最強。
- A 的芽在 48px 仍可辨，但身體通用、夜間發平。
- B 依賴動態；靜態易讀成燈泡或蘑菇，64px 時臉已看不清。

**角色差異化潛力**
- C 最強：換紙材，剪影、質感、動態節奏一起變。
- A 有「接收器官／筆觸／移動方式」三軸，清楚好用。
- B 的「液體的不同時刻」很有詩意，但大家都是軟團，剪影差異只能靠形變。

**動態表現潛力**
- B 天花板最高，但每一招都是非剛體。
- A 中高：只有芽一個形變點。
- C 中等，但折、伸縮、翻面、小紙片延遲都很有性格，而且全是剛體。

**實作成本**
- C 最低，約 7–10 人日：日夜共用一組圖，不需要 Rive。
- A 中等，約 9–12 人日：日夜要兩組圖，芽要多狀態或骨骼。
- B 最高也最難估，約 12–16 人日：紙紋不能跟著形變、要和色塊引擎耦合、夜間池色對不上。

**拆件品質**
- A 的群組父子關係與 pivot 最完整，但 SVG 本身不是合法 XML。
- B 的 mask 接縫處理得好，但紙紋烘在部位裡。
- C 的手不在身體群組下、腳包在腿裡、折角缺正面，三個都是一次修訂就能補的結構錯誤。

## 推薦

我推薦 A 聽芽作為主方向，最終選擇權在業主。理由如下：
- **情感與可愛度**：它在「情感感染力」與「可愛親和」兩個業主最在意的面向最強。
- **結構最接近理想**：除了芽之外全是剛體，拆件群組與 pivot 最完整，濾鏡成本最低。四段動態用 CSS／WAAPI 就能完成第一期，招牌的芽日後可以單獨升級成 Rive 骨骼。
- **媒材正中業主優先**：色鉛筆排線加一支筆輪廓，正是業主優先的方向，也和網站現有的手繪線條同一種手感。

它目前的問題都能在一次修訂內修好：XML 不合法、芽要拆兩段以降低狀態數、夜紙的明度對比。

**若業主更重視以下幾點，C 摺摺是很強的第二選擇：**
- 原創材質、不像通用吉祥物
- 最低的實作成本
- 一組圖就能撐日夜兩種紙

它的系列化潛力其實三案最高，代價是臉偏僵、色調偏灰，也離色鉛筆／蠟筆最遠。

**B 漾漾不建議當主角色，但它的世界機制最值得保留。** 它和首頁世界觀的契合度最高，可是每個招牌動作都是非剛體：紙紋會被拉伸，要和色塊引擎耦合，夜色池子也對不上，實作風險最大。比較划算的是把它的「池子相融、漣漪」降為所有角色共用的世界機制（見混合建議），而不是讓主角色本身是液體。

## 混合建議

一、A 的角色，加上 C 的「紙片」做法

- 把聽芽的色鉛筆畫放在一片撕下來的紙上：外緣一圈白纖維撕邊，像剪下來貼在頁面上。
  - 實作：A 的 a-under 打底層改用 C 的 c-paper 撕邊和白纖維 rim。
- 好處：
  - 一次解決 A 夜紙發平的問題，撕邊在夜紙上本身就是輪廓。
  - 解決 A 站在桃色色塊前不夠跳的問題。
  - 豆形身體多一層原創的材質辨識。
- 動畫仍是 A 的剛體拆件，而且日夜可以共用一組烘焙圖，省掉 A 的第二組素材。

二、B 的池子，降為所有角色共用的世界機制

- 每隻角色腳下的影子不再是排線，而是讓首頁 DriftingBlobs 多畫一個跟著角色走的小 lobe，用角色自身的淡色，也就是腳下一小灘顏色。
- 兩隻角色靠近時，兩灘影子會長出頸部、混色、融合。這直接用現有 metaball 程式；World 已有 lobeAt 與 blend。
- 角色本身維持剛體，便宜又穩，「共振」的那一刻卻和首頁色塊說同一種語言。
- 夜間這一小灘取夜色塊的色值，就不會有 B 池子亮薰衣草對不上的問題。

三、A 的芽尖輕碰，加上 B 的漣漪

- 兩隻角色的芽尖（或 C 的折角）碰到的瞬間，從接觸點漾出兩三道波線。
- 波線用既有的 wavyPath 和「一支筆」主線寬，形狀就是 logo 的三道波浪。不用新增任何素材，只是一次 stroke-dashoffset 加 opacity 的動畫。

四、C 的系列化軸，借給 A

- 世界觀維持「被故事養大、各有接收器官的小生物」。每一隻新角色換一種「紙加筆」的組合：
  - 聽芽：色鉛筆在畫紙上
  - 下一隻：蠟筆在牛皮紙上（B 的蠟筆質感有了歸宿）
  - 再一隻：水彩在厚紙上
- 剪影由器官決定，質感由紙和筆決定，兩條軸疊起來，就不會淪為換色。
