## Rate limits, auth, the contract

**Rate limits** (`src/lib/api/rateLimit.ts`): costly or far-reaching endpoints spend a per-user budget (`spend()` in v1 routes, `limited()` elsewhere) kept in server-only `rateLimits/{uid}_{bucket}`; over budget answers 429 `rate_limited`.
A new LLM, upload or notify endpoint should take a bucket.
`resonate` is 20 a day: picking a card connects, taking it back disconnects, and the pair must not become a way to reach anyone.
`trash` and `restore` are separate (200 a day each), so clearing many cards never spends what an undo needs.
`react` (300 a day), `unsend` and `stopShare` (100 a day each) bound the quiet writes on someone else's thread.
`read` (500 a day) bounds counting reads on others' cards.

API routes authenticate with the `__session` cookie **or** `Authorization: Bearer <Firebase ID token>` (native apps) — both via `getCurrentUser()`.

**`/api/v1` is a contract.** Zod schemas in `src/lib/api/v1/schemas.ts` are the source of truth: routes validate with them (`withUser` + `parse` in `http.ts`, errors always `{ error: { code, message, issues? } }`), and `npm run api:openapi` writes `openapi/v1/openapi.json`, from which the iOS (swift-openapi-generator) and Android (openapi-generator) clients are generated.
Within v1 change additively only; clients tolerate unknown fields (no `additionalProperties: false`), and optional request fields accept `null` (Kotlin clients send it, Swift omits it).
Two additive-looking changes still need the apps touched in the same change, or they stop compiling: a status newly documented on an existing operation (the iOS kit `switch`es over each operation's documented answers — e.g. `WritingAPI`'s `.conflict` cases for the trash's 409), and a value added to a request enum the apps switch over (the card box shelves: `trash`); a new enum in an answer joins iOS `OpenEnums.fields`.
The services (`service.ts`, `reads.ts`; shapes in `present.ts`) run on the Admin SDK, which bypasses `firestore.rules` — every guarantee the rules give the web client (blocks, quotas, visibility) must be re-checked there and covered in `test/emulator/apiV1*.emulator.test.ts` (`canView` in `present.ts` is `cardVisible`).
Every v1 GET answers through `cachedJson(req, body, OWN | BRIEF | NEVER)` (`src/lib/api/v1/cache.ts`): always `private`, never `s-maxage`; ETag + 304; `Vary: Authorization, Cookie, X-Resonance-Cache`.
The viewer's own things are `no-cache`; others' cards, profiles and lists may be reused 30 s, and the recommended feed until UTC midnight when `fresh` (`no-store` when `stale`) — but only by clients that send `X-Resonance-Cache: 1` (the current apps, whose caches are per account and re-ask after the viewer's writes); everyone else revalidates.
Any server path that makes a card non-public, anonymous or gone revalidates its pages with `revalidateLocalized([...cardPagePaths(card), ...landingPagePaths(before, after)])` from `src/lib/api/revalidate.ts` (the purge's `PurgeReport.pages` does it for the cron) — never the author's `/u/{handle}` for a card change (PATCH, delete, edits/apply, trash, restore, both purges): that page's HTML holds no cards, and starting its cache afresh as an anonymous card changed would tie the card to that profile (Age / x-vercel-cache); `profilePagePaths(handle)` is for changes to the profile itself (POST/PATCH /me, the account purge). v1 lists read cards with `LIST_FIELDS` (`summary.ts`) and show their stored `excerpt`/`readMinutes` (the excerpt by `lib/markdown/plainText`, shared with the web's own story cards: Markdown and bare addresses out, character references and backslash escapes read as the text they stand for — the editor stores `->` as `-&gt;` — never as syntax; every pattern bounded, so no story the rules take is read in more than a moment, on the server or in a browser; after a change to it, `backfill-card-summaries.ts --write` restates the stored ones that differ), falling back to the story when `updatedAt` is later than `excerptAt`: a server write that changes a published card's story spreads `summaryFields(story)`, and one that changes nothing a list shows doesn't bump `updatedAt`.
Response enums are a closed contract (normalize with `visibilityOf()`; a new value is a breaking change).
Every v1 answer has `Server-Timing` (`auth`, `app`, `cold`); `FIRESTORE_PREFER_REST=1` puts the Admin SDK on REST to compare cold starts.
Routes whose parameter is a card id (resonances/related/links, notes' `cardId`, messages' `cardRef`) read by id only (`visibleCardById`); only `GET /cards/{key}` and report resolve slugs (`cardByKey`), before the document read, never beside it.
Lists check visibility with `visibleTo()` (one batched connection read per author).
