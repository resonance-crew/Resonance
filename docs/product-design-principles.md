# Resonance · Product Principles
# 共振的設計準則

從兩個定位維度出發的功能哲學 —— 為什麼我們這樣做，以及為什麼我們不做那些。

---

## 序：兩個定位維度

所有的功能爭論，最後都會回到兩個定位問題：**使用者的身份要多真實？內容要限定在什麼範圍？**我們的答案是——身份保留彈性，內容徹底鎖定。

### 【定位維度示意】

*   **維度一：使用者身份**
    ```
    完全匿名 ────────────────── [ 帳號真實、展示自選 (保留彈性) ] ────────────────── 完全真實
    ```
*   **維度二：內容類型**
    ```
    虛構・情緒抒發 ─────────────────────────────────────────── [ 有體悟的真實故事 (徹底鎖定) ]
    ```

> *設計哲學：身份是一段可移動的範圍；內容是一個焊死的點。*

值得所有人知道的一件事：*第二個維度已經寫進架構*。每張卡片發布時，AI 會讀完整篇故事，寫下它的每個體悟：作者遇到什麼處境、卡在哪裡、怎麼想、得到什麼、有什麼轉變，並判斷這張卡是不是只有感受、沒有體悟。**只有帶著體悟的卡片才會推給陌生人**，純流水帳照樣發布，只是不會被主動推薦。定位是用程式碼強制執行的（詳見文末附錄）。

## 〇、核心哲學：訊號只描述讀者自己，從不替卡片排名

> 草稿（第 26 輪，2026-11-19）：伺服器車道起草，主導者修訂，擁有者在推送前讀過才算數。

推薦系統會讀讀者自己做過的事：寫過、用卡片回應過、寄過小紙條、按過共振、收藏過、讀到最後、回來重讀、分享出去。這些訊號只用來替**這一位讀者**挑卡，描述他的口味。沒有一張卡會因為很多人讀過、很多人共振，就被推給更多人。

### 不做的事（Not-Doing List）

*   **只有一種共振。** 共振就是「這篇和我有共鳴」，不分讚、愛心、哈哈。按下去的人只表示一件事，讀的人也只需要讀懂一件事。
*   **沒有公開的數字。** 卡片上不顯示共振數、閱讀數、收藏數。讀者看到的是自己連結的人的臉，作者看到的是誰共振了，名單多長就是多少人，不另外放大成數字。
*   **系統自己記下來的東西，不帶名字。** 讀了多久、讀到哪、有沒有重讀，只拿來替讀者挑卡。作者只會收到一週彙整的「上週有 N 個人把這張卡讀到最後」，三個人以上才說，而且不說是誰。
*   **訊號描述讀者，從不描述卡片的熱門程度。** 挑卡的程式碼裡不准出現任何「這張卡被多少人做過什麼」的欄位，`src/lib/recommend/noPopularity.test.ts` 會擋下來。也不做「共振過這篇的人也喜歡……」。
*   **沒有熱門榜、沒有趨勢。** 首頁、推薦、晚間推播都不排「最多人看」。
*   **按共振是安全的。** 按下去不會讓你和作者連結，作者也不能因此私訊你（他的名單點你只會開到你的個人頁）。收回不通知任何人。你的臉只會出現在你連結的人和作者面前。
*   **只有感受、沒有體悟的卡，不推給陌生人。** 它照樣發布、照樣在動態和個人頁上，任何人都讀得到，只是推薦、相關卡片、首頁影片和晚間推播不會主動拿給不認識作者的人。

> **為什麼這樣排？**
>
> 免費又能被統計的動作，一旦拿來排名，就會被優化。被優化的動作會讓大家開始表演，那正是演算法社群一路走偏的地方。把訊號限定在「替這個人挑卡」，它就只能讓推薦更懂這個人，沒辦法讓哪張卡變成明星。

### 為什麼改了（2026-11-19）

原本這一節寫的是：「推薦系統裡唯一被採用的互動訊號，是這位讀者曾經為哪些作者寫過一張共振卡。讚數、停留時間、點擊率全部被明確拒絕。」理由是零成本的動作會被優化，只有寫一張回應卡夠真誠。

第 26 輪改了，因為擁有者要把收藏、共振、回覆、閱讀時間和重讀都放進推薦。兩個擔心仍然成立：廉價訊號會被優化，停留時間不等於喜歡。這一輪的回答是：

*   訊號全都只描述讀者自己的口味，任何一個都不會累加到卡片身上，所以沒有東西可以刷。
*   時間訊號修正過：沒有回報的打開不算負分（舊版 App 和被系統關掉的頁面本來就沒有回報），一份回報說只停了不到 10 秒、讀不到一成，才算「打開就離開」。
*   最重的仍然是有代價的動作：用卡片回應 5、寄小紙條 4、按共振 3、讀到最後 1（權重都在 `src/lib/recommend/weights.ts`）。

遇到新的功能爭論時，先問：*這個設計讓某張卡被更多人看到，靠的是它對讀者說了什麼，還是有多少人碰過它？*

## 一、公開的回應只有一種——成為作者

「要不要做留言區」的爭論，癥結其實不在留言區本身。FB / Threads 式的留言區之所以產生創作者與觀眾的主從關係，是因為它把兩種本質不同的行為混進了同一個公開空間：**對作者說話**（我很感動、我也經歷過），和**對觀眾表演**（搶樓、抖機靈、站隊）。留言區有觀眾，說話就會變成表演。

所以我們不做二選一，而是*按「說話的對象」把回應拆成三層*：

### 【三層回應結構】

第 26 輪起，一篇故事底下有三種回饋：按**共振**、**寄小紙條**、**用卡片回應**。**收藏**和**分享**是被動的，放在旁邊。

1.  **收藏（對自己說）**
    *   **描述：** 純私人、不顯示計數、不通知任何人。
    *   **成本：** 最低
2.  **共振（對作者點頭）**
    *   **描述：** 一個按鈕，意思只有「這篇和我有共鳴」。作者看到是誰，讀者看到自己連結的人裡誰也按了（只有頭像，不寫字、沒有數字）。不連結任何人，收回不通知。
    *   **成本：** 低
3.  **私下回應（對作者說）**
    *   **描述：** 一張只有作者看得到的小紙條，就在故事下方原地寫，不開對話框，沒有觀眾、不公開、不計數。
    *   **成本：** 低
4.  **用卡片回應（對世界說）**
    *   **描述：** 唯一的公開回應：寫一張自己的卡片。回應者即作者。
    *   **成本：** 高・唯一公開

> *設計哲學：對自己說、對作者點頭、對作者說、對世界說。公開層只有一種形式。*

這個結構同時回答了三個原本各自為政的問題：

*   **「我很喜歡，已收藏」的出口** —— 收藏與私下回應承接了所有輕量回饋，讀者不再被迫在「寫一張卡」和「沉默離開」之間二選一。
*   **主從關係** —— 讀者對作者的話走私下通道，沒有觀眾就沒有表演，也就沒有台上台下。
*   **作者的安全** —— 寫下脆弱真實故事的人，不必面對公開留言區裡的嘲諷、獵奇與審判。私下回應反而比公開留言更真誠。

### 共振的門檻，用編輯器解，不用留言區解

共振門檻高是事實，但解法不是增設低門檻的公開通道，而是**降低寫作本身的門檻**。點下共振的那一刻，系統早就擁有那張卡的核心體悟——可以讓 AI 用它起頭：「這張卡片的體悟是 X，你有過類似、或完全相反的經驗嗎？」並且允許共振卡很短——三五句話的「回聲」也是一張卡。門檻的本質不是「要寫字」，而是「面對空白編輯器不知從何說起」，而我們手上剛好有解決它的素材。

*額外的機會：私下回應可以成為共振的前奏。作者收到紙條後回一句「這段經驗我很想聽，願意寫成卡片嗎？」——被邀請而寫的第一張卡，比自己鼓起勇氣發的容易得多。*

## 二、身份彈性下放到每一張卡

把兩個定位維度放在一起，會得到一個必然的推論：**真實故事常常是脆弱的內容**。一個平常願意用真名的人，寫到離婚、憂鬱症、家庭創傷時可能就不願意了。如果身份彈性只存在於帳號層級，這些體悟濃度最高的故事就不會被寫出來——或者使用者會去開小號，我們反而失去「背後有真實身份、糾紛可調解」的底層保證。

### 【身份三層結構】

*   **▲ 卡片層：可匿名**
    *   單張卡片可選「以匿名發布」・不掛名、不進公開個人頁。
*   **■ 展示層：自選**
    *   暱稱或真名・頭貼放不放・像 Facebook 一樣給選擇。
*   **▼ 帳號層：真實**
    *   註冊時完成真實身份環節・平台可追溯・糾紛可調解。

> *設計哲學：越往下越真實、越往上越自由：信任建立在底層，勇氣發生在頂層。*

*   **帳號層真實** —— 註冊時有真實身份認證環節。這是平台調解糾紛、維持信任的地基，永遠不對外展示。
*   **展示層自選** —— 要用暱稱還是真名、要不要放頭貼，交給使用者。我們傾向真實，但不強迫。
*   **卡片層可匿名** —— 單張卡片可以選擇匿名發布：不掛名、不出現在公開個人頁，但平台後端知道作者是誰。最脆弱的故事，往往就是最值得被寫出來的故事。

*工程注意事項：匿名卡的向量照樣進作者自己的推薦畫像（私人內容本來就只影響本人的推薦），但公開候選池的記錄帶有作者 ID，「共振作者加分」等 join 路徑必須確保不會間接洩露匿名卡的作者身份。*

## 三、關係從故事裡長出來

「遇到心靈契合的人」是我們的目標之一，但**無門檻的通用私訊是重災區**——騷擾、搭訕、詐騙都從那裡開始，而我們的使用者剛剛在平台上袒露了人生最脆弱的部分。所以私訊不是一個平行蓋起來的聊天室，而是*要用故事賺來的東西*：

### 【從故事到私訊的路徑】

```
[ 讀到打中你的故事 ] ───> [ 私下回應或寫共振卡 ] ───> [ 連結邀請，雙方同意 ] ───> [ 私訊開啟 ]
```

> *設計哲學：陌生人之間唯一的接觸路徑——每一段對話的開場白，都是一個具體的故事。私訊藏在關係的最深處，而關係的入口永遠是作品。*

這條路徑剛好搭在我們已有的一對一連結（invite / connection）機制上，不需要新的信任模型。它保證私訊的第一句話永遠有脈絡——不是「嗨，在嗎」，而是「你寫的那張卡」。

### 群組：先不做。想要「一群人」，用主題圈

群聊會把平台的重心從「寫」拉到「聊」，管理成本極高，而且即時訊息天然獎勵快與淺。如果之後想要群體感，更貼合定位的形態是**主題圈／故事集**：一個題目（「第一次送別」「離開穩定工作的那天」），大家各自投入卡片、圈內互相共振。它是非同步的、以作品為中心的聚集——不是聊天室，是一場不散的展覽。這同時也解決了冷啟動時期的內容組織問題。

## 四、冷啟動：先寫，也可以先讀

推薦畫像原本只從「你寫過什麼」建立，從未寫過卡片的人沒有個人化的 feed。第 26 輪起，讀過、共振過、收藏過的卡也算數，所以一個只讀不寫的人也拿得到推薦。

什麼都還沒做的人，先看到自己連結的人最新的具名公開卡，再看到一組「彼此最不像」的卡（涵蓋組，每天換一個起點，不叫模型）。有一兩張表態過的卡時，8 張裡有幾張照口味挑，其他來自涵蓋組。三張以上就照口味，留一個位置給他還沒讀過的生活領域。

> **產品含義**
>
> 註冊後的第一件事仍然是被陪著寫出第一張卡。差別是，在那之前讀到的每一張卡，都已經在替他排列下一張。

## 五、AI 是鏡子，不是守門員

系統為每張卡萃取體悟簽名、為每次推薦產生理由。這些能力該怎麼露出，有兩條紅線一條機會：

*   **把推薦理由亮出來。** 選卡的模型本來就會寫下推薦理由——直接顯示在 feed 上：「推薦給你，因為你寫過的某個體悟和這篇呼應」。透明的推薦是對黑盒演算法最鮮明的差異化，也讓使用者理解「我寫什麼，決定我看到什麼」，反過來激勵寫作。
*   **把簽名回顯給作者。** 發布前告訴作者「我們讀到的核心體悟是：……」。寫作者常常自己都沒意識到寫出了什麼——這是一面鏡子，也是很動人的產品時刻。
*   **但永遠不顯示體悟分數、不說「體悟不足」。** 分數只在後台安靜地決定一張卡要不要推給陌生人。AI 沒有資格公開裁判一個人的人生領悟。發布前的鏡子讀不到體悟時，就什麼都不說。
*   **推薦理由不說你做過什麼。** 理由不寫「你讀過」「你收藏了」「你共振過」，也不點名敏感的處境（疾病、喪親、自傷、離婚……）。晚間推播會出現在鎖定畫面上，拿著手機的人不一定是本人。

---

## 六、指標必須跟上價值觀

程式碼層面我們已經拒絕了讚數與停留時間，但如果營運指標還在看 DAU 和 time-spent，遲早會有壓力把讚數加回來。北極星指標應該量我們真正想要的東西：

### 【指標對照】

| 我們不量 (❌) | 我們量 (✅) |
| :--- | :--- |
| DAU・停留時間 | 每位讀者每週寫出的共振卡數 |
| 讚數・點擊率 | 私下回應 → 共振的轉化率 |

> *設計哲學：量表演，得到表演；量真誠，才有機會得到真誠。*

## 附錄：體悟推薦系統現況（第 26 輪）

供還沒看過程式碼的成員參考。系統分成寫入端與讀取端，成本刻意壓在寫入端（每張卡寫一次、改一次）：

### 【推薦系統管線圖】

```
【寫入端（發布時一次，之後的修改由每天的排程重讀）】

  [ 卡片發布 ]
       │
       ▼
  [ AI 讀全文 ] ── (每個體悟：處境、困境、想法、收穫、轉變、體悟；只有感受？分數)
       │
       ▼
  < 給陌生人嗎 > ─── (是) ───> [ 每個體悟兩份向量 (候選池) ]
       │
       └── (否) ───> 照樣發布，但不推給陌生人
```

```
【讀取端（每天替每位讀者算一次）】

  [ 讀者自己做過的事 ] ── (寫過、回應、紙條、共振、收藏、讀完、重讀、分享)
       │
       ▼  (1) 每張表態過的卡投票：候選池裡每張卡跟它多近 (整池精算，先減平均、扣掉跟誰都近的程度)
  [ 最接近的 30 張 ]
       │
       ▼  (2) 輕量模型重排
       ▼  (3) 拉開差異 (MMR)，同一作者最多 2 張
  [ 12 張 ]
       │
       ▼  (4) 選卡模型挑出最多 8 張，附上推薦理由
  [ 最多 8 張推薦 ]
```

> *設計哲學：寫入端讀全文、把一張卡拆成幾個具體的體悟，讀取端只看這位讀者自己做過的事。*

幾個支撐前文準則的既有設計：

*   **一張卡是幾個體悟。** 長一點的故事最多三個體悟，各自一份「想法與收穫」向量、一份「處境與困境」向量。兩張卡多近，看最接近的那一對體悟，再加一點處境的相近。
*   **匿名卡不洩露作者。** 讀者在匿名卡上的動作只進他的內容口味，「回應過這位作者，他的新作加一點分」只算具名卡。
*   **不夠 8 張就少給。** 候選池不夠時不拿看過的卡來湊。明確表態過的卡（回應、紙條、共振、收藏）不會再推。只讀過的卡 30 天後可以再出現，推了三次都沒打開的卡停 14 天。
*   **私人卡只影響本人。** 讀者讀過的卡、自己的私人卡，都只拿來替他自己挑卡，向量永不外洩。
