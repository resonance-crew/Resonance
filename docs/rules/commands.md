# Commands — the full list

The root [CLAUDE.md](../../CLAUDE.md) lists the everyday ones; this is every command it used to list, with every flag and what each does.

## Commands

```bash
npm run dev        # Start Next.js dev server
npm run build      # Production build
npm run lint       # ESLint (flat config, plain `eslint .`)
npm run typecheck  # tsc --noEmit
npm test           # Vitest, single run (CI mode)
npm run test:watch # Vitest in watch mode
npm run test:ui    # Vitest browser UI
npm run emulators       # Firebase Auth + Firestore emulators (needs Java; project demo-resonance)
npm run dev:emulator    # Next dev server wired to the emulators (no real Firebase/R2 is touched)
npm run test:emulator   # Rules + Admin SDK suites in test/emulator (starts/stops the emulators itself)
EMULATOR_AUTH_PORT=9199 EMULATOR_FIRESTORE_PORT=8180 npm run emulators:at [-- "<command>"]   # a private pair of emulators beside the shared ones (dev:emulator, seeds and the apps' emulatorAuthPort/emulatorFirestorePort/emulatorApiPort launch args follow the same variables)
npm run moderation -- list [--emulator]   # read the report queue (reports are write-only for clients); `show <id>` prints one with its kept evidence, and what became of a reported card since (live, private, in its author's trash until when, gone); `picture <imageId> [file]` saves a chat picture a reported message carried (its evidence names it by `image.id`)
npx tsx scripts/backfill.ts <anonymous|handles|edits|storage-host|rekey-images|rehost-images|square-avatars|reencode-legacy|avatar-colors|notes|anonymous-bells|orphan-notes|card-tombstones|link-previews> [--apply] [--emulator] [--delete-old] [--missing]   # older data the rules now expect (dry run unless --apply); rehost-images moves stored picture URLs off a former storage host (see Storage); square-avatars cuts profile photos stored before photos were cut square as a new one is (256 px WebP, new key on record, the old picture kept; reads them by public URL — run with the deployment's R2_PUBLIC_BASE, which the local .env may predate); reencode-legacy re-encodes stored pictures still in a format uploads no longer keep (an `image/…` key that isn't WebP or AVIF — covers, story pictures, pending edits, profile photos) as an upload is now (`normalizeUpload`: WebP ≤ 2048 px, a profile photo cut square), under a new key on record as their owner's (`storeOwned`), the documents pointing at the copy as rehost-images rewrites them (no `updatedAt` or summary change, `reportEvidence` left as it was), the old files kept; a dry run lists each picture, its size, what would replace it and every document naming it (reads them by public URL — the deployment's R2_PUBLIC_BASE, with R2_FORMER_PUBLIC_BASES; on the emulator, the emulators' own picture folder); avatar-colors gives each profile still wearing the one avatar colour every profile was once given (or none) its own, by uid, as a new profile gets one (`avatarColorFor` in `src/lib/design/avatarColors.ts`); anonymous-bells gives older note and resonance bells on anonymous cards `payload.anonymous` (what their push and the bell lists route by: the card, not the writer's thread — see Push); card-tombstones gives the ids of cards deleted before deleting one left a tombstone (`cardTombstones/{id}`, no uid; the rules refuse a new card under one) when something still names them — a resonance, a bookmark, a thread's card, a bell, a thought-map node, a card link, a pending edit; link-previews gives published cards their story links' previews (`--missing` also asks again for links tried before that have none — after previews learn a site, as YouTube's videos; a dry run also lists each published paragraph whose card-ness the words rule changed — card id, paragraph start, link; fetches the pages; --apply on production refuses without LINK_PREVIEW_SECRET or FIREBASE_PRIVATE_KEY — the deployment's — and says which signs); notes carries notes left before they went into the thread into it (see API Routes — it can bring back a conversation someone deleted, so a production run is the owner's call); orphan-notes deletes notes whose card is gone (older builds' client deletes, a clean-up that failed after the card went) and those still on an anonymous card in the trash (they go as it goes in; notes naming no card are only reported — a production run is the owner's call)
npx tsx scripts/backfill.ts recommend-index [--all] [--apply] [--emulator]   # round 26's card reading (the whole story into its insights, server-only in cardSignatures) and its parts' vectors for published cards — those not read by this recipe yet, or every one with --all — two at a time, 500 ms between; a dry run counts and estimates tokens and cost, an applied run prints what it spent; then the older recipe's fields go from cards and readers' stored picks lose their items and day (askedOn and shown kept). Replaces scripts/backfill-recommend-index.ts; production runs are the owner's call, after the push
npx tsx scripts/backfill-card-summaries.ts [--write] [--all] [--emulator]   # list summaries on older cards (dry run unless --write)
npx tsx scripts/integrity.ts [--emulator]   # read-only check for data the rules would refuse today (and published cards or pending edits anonymous and for connections only, which are left as they are; and cards the trash left half done — not private, still pointing, past the purge, an anonymous one still holding notes)
npx tsx scripts/recommend/nearest.ts [--from <dryrun.json>] [--card <slug|id>] [--top <n>] [--pair <a>,<b>] [--pairs <file.json>] [--within <n>] [--funnel] [--cosine [--channel situation] [--fulltext]] [--out <file>]   # read-only diagnostic of the recommender's matching, on production or on a dry run's file (`--from`): each public card in the candidate pool, how much of its story the reading model was handed, what it wrote, and the cards it stands nearest to by the funnel's own card score over its parts (lib/recommend/match: centred, CSLS, MaxSim + 0.3 × situation; the report is in Chinese, the cards' language); `--pair` says where two cards the owner takes to share an idea stand for each other, and `--within` fails the run when they stand further apart; `--funnel` runs the picking path for one card taken as a reader's only positive and says whether its pair made the 8 (no LLM step); `--cosine` is the older one-vector view of the stored index (with `--fulltext`, a second ranking from each card's whole text, sent to OpenAI's embeddings); public cards only, never a writer
npx tsx scripts/recommend/dryrun.ts --model <id> --embed <id> --out <file.json> [--limit <n>] [--card <slug|id>] [--concurrency <n>]   # the model bake-off's dry run (round 26 §E1): production's public cards read read-only, each given round 26's reading and its parts' vectors in memory with the models named (the cards' text goes to OpenAI), written to a local file for `nearest.ts --from`; prints tokens and cost; writes nothing to Firestore and names no writer
npm run api:openapi     # regenerate openapi/v1/openapi.json from the Zod contract (a test fails when stale)
npm run native:editor   # typecheck + build the native apps' editor island (native/editor/dist/editor.html)
npm run apps:generate   # regenerate what the native apps take from the web (tokens, strings, OpenAPI, editor)
npx tsx docs/store/graphics/render.ts og   # the site's share image (the platform cover): public/og-cover.jpg + og-cover.en.jpg, 1200 × 630, from the App Store header's recipe; bump OG_COVER_VERSION in src/lib/og.ts after redrawing it
npm run stickers -- [pack | pack/id | pack/icon] [--serve <port>] [--out <dir> --fast --frames <dir>]   # the 小紙團 stickers (designs/stickers → public/stickers/<pack>/<id>.webp + .thumb.webp + icon.webp, then the catalog); `npm run stickers:parts` re-exports the puppets' parts at 2×; after merging packs drawn apart, `npx tsx scripts/stickers/catalog.ts` regenerates src/lib/stickers/catalog.generated.ts, public/stickers/catalog.json and the review page's data
npx tsx scripts/promo/render.ts [--locale zh-TW|en|all] [--preview] [--stills 12.5,30 --stills-dir <dir>] [--silent]   # the README's one-minute tour (scripts/promo/page, drawn with src/lib/design and the tokens) → docs/media/resonance-intro.{locale}.mp4 with its soundtrack scripts/promo/score.m4a (ElevenLabs Music, made under the owner's commercial licence and not MIT — see THIRD_PARTY_NOTICES; the picture is timed to it, so a new score means checking the 24–36 s swell and the 58 s ending) (+ with --preview the README's looping .avif and its .jpg still); needs Chrome (CHROME_PATH) and ffmpeg with libx264 and libsvtav1; the app's own strings come from src/messages, so re-render after renaming one it shows
npm run visual -- capture [web android ios mac] [--only <screen ids>] [--device <id>] [--flows] [--review]   # release screenshots: every screen of scripts/visual/screens.ts on web (phone/tablet/desktop), iPhone, iPad, the Mac app and Android phone/tablet, against a private seeded stack, two at a time (web + Mac, the AVDs, the simulators), diffed with this machine's baseline (areas moved more than 2 px, `scripts/visual/diff.ts`) (visual/, git-ignored); `--review` hands what changed to Antigravity's CLI (`agy`); `review --run <id> --agy`, `accept --run <id> [--only …] --reason "<the owner's words>"` (refused without one; logged in docs/visual-accept-log.md) — scripts/visual/README.md says which devices, sizes and settings, and why
npx tsx scripts/visual/flows.ts <android|ios> [--only <flow>]   # Maestro interaction flows (maestro/flows) on the harness's own phone simulator/AVD — maestro/README.md
npm run visual -- capture … [--variants release|extended] [--flows [--tags <tags>]] [--wait] [--force-build]   # --force-build builds the apps even when their inputs match the last build (buildStamp.ts); a run that stops moving or runs too long ends (watchdog.ts); --variants extended adds large text on the Android phone, the tablets turned and in the dark, a narrow Mac window and the composer's extra states (scripts/visual/variants.ts); one run at a time per device and port (lock.ts: refused, or --wait to queue); never shuts down a device it didn't boot
npm run visual -- plan   # how many captures each variant set takes, and about how long
npx tsx scripts/visual/flows.ts <android|ios> … [--tags smoke|composer|media|links|…] [--device phone|tablet] [--wait]   # a tagged group of flows, or the tablets — maestro/README.md
scripts/lane.sh <round> <web|ios|android|server|mac|base> [base]   # a round's lane: the sibling worktree, its setup (node_modules and visual/ linked, .env*, local.properties, native/*/dist), private ports — prints LANE_* lines; docs/agents/lane-brief.md
npm run -s acceptance -- <acceptance.json> [--lane <l>] [--all-pass] [--against <signed.json>] [--run [--cwd <dir>] [--write]]   # a round's acceptance list: checks it, runs its verify commands, sets `passes` (docs/agents/README.md)
npm run -s agents:models [-- --write]   # the round agents' models, from .claude/agents/models.json
npm run test:loop   # the round tooling's tests (scripts/round); `npm test` runs them too
npm run -s rules:commits -- <base>..<head>   # what CI's `commits` job checks: a `Visual:` line on every commit touching UI, a test with a data-layer change (scripts/ci/commitRules.ts)
npm run release:preflight [-- --rev <commit>]   # before a store release: one PASS/FAIL line per check (CI on the commit, versions, the web live first, rules deployed, docs/release/owed.md, the last full visual run, the accept log), `Preflight PASS|FAIL` last, exit 1 on a FAIL
npm run release:bump -- <x.y.z|patch|minor|major> [--ios-build N] [--android-code N] [--write]   # both apps' versions; a dry run printing the diff and the `build: 🔖` subject unless --write
npm run release:export -- [--commit <rev>] [--dest <dir>] [--no-keys] [--dry-run]   # the clean export store builds come from (git archive, links, islands, xcodegen); builds nothing
npm run ops:daily [-- --data skip|emulator|production] [--since 24h] [--out <file>]   # the read-only daily report: CI on main, Vercel production and its error logs, store review states, moderation and integrity counts (docs/ops/daily-check.md)
npx tsx scripts/ops/link-preview-secret.ts [--from <env file>] [--check '<stored /api/link-image?u=…&s=… path>']   # prints the `derived-v1:…` LINK_PREVIEW_SECRET that signs exactly as the key derived from FIREBASE_PRIVATE_KEY (local env only, never calls Vercel); --check verifies a stored picture's signature with it (exit 1 if not) — docs/release/owed.md
npm run test:release   # the release and ops scripts' tests; `npm test` runs them too
```

Seed the emulators with known test accounts: `npx tsx scripts/seed-emulator.ts`. In a `dev:emulator` browser, sign in from devtools with `await window.__emulatorSignIn(email, password)` (values in the seed script) — that helper exists only in emulator builds.
npx tsx scripts/perf/write-paths.ts   # (run under `npm run emulators:at`) times the write paths (publish by audience, save, edit, 共振 tap/pick, note, reply, chat) and a notification's first reads on the emulator, step by step; PROBE_RTT_MS adds latency to every awaited call, PROBE_SLUG_MS simulates the slug model, PROBE_ROUNDS the median's runs (round 32 §P6)
